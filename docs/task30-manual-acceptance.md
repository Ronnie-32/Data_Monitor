# DeskBoard 设置与主题人工验收流程

这份流程用于验收设置页面重做、主题、字体和中英切换。它需要在正常 Windows 桌面会话中执行，不能只用静态代码检查或自动化测试代替。

## 一、验收准备

1. 使用 Windows 10/11 64 位的正常桌面会话，建议分辨率至少为 1280×720。
2. 关闭其他 DeskBoard 进程，保留一个干净的用户桌面环境。
3. 准备截图工具或屏幕录制工具；每个失败项至少记录截图、操作步骤和时间。
4. 如果要同时验收天气或金融数据，先记录当时是否使用 VPN、代理或 Clash。UI 验收不应因为某个外部数据源暂时失败而被误判为通过。

当前最新改动请使用源码入口启动：

```powershell
$env:PYTHONPATH = (Resolve-Path 'src').Path
.\.venv\Scripts\python.exe -m deskboard
```

当前 `dist\DeskBoard\DeskBoard.exe` 和 `dist\installer\DeskBoard-Setup-0.1.0.exe`
早于本轮界面修复，不用于验收本轮结果。

每项结果填写为 `PASS`、`FAIL` 或 `BLOCKED`。`BLOCKED` 必须写清楚阻塞原因，例如应用无法启动、权限异常或外部数据源不可达。

## 二、启动和设置页面

### MAN-UI-01 启动与首次设置

1. 启动 DeskBoard。
2. 确认 Dashboard 出现，系统托盘图标出现，程序没有弹出第二个重复窗口。
3. 打开 Settings，观察窗口标题区、左侧导航、内容区和底部操作区。
4. 依次点击 `General`、`Profiles`、`Weather`、`Finance`、`Todo`、`Courses`、`Data Status`、`About`。

预期结果：

- Settings 是独立的原生设置窗口，页面切换稳定，没有白屏、黑屏或明显闪烁。
- 八个页面都可以打开，侧栏选中状态清楚，标题和内容没有被截断。
- 窗口缩放到较小尺寸后，控件仍可见；不要求所有内容在小窗口中完全不滚动。
- `Profiles` 和 `Weather` 页面内容较长时可以在页面内滚动，不应因为窗口高度不足而把控件压成重叠或黑色区域。

### MAN-UI-02 默认中文

1. 关闭并重新启动程序，或在 Settings 中恢复默认语言后重新打开 Settings。
2. 检查侧栏、页面标题、按钮、选择框、提示语和 About 页面。

预期结果：首次使用和默认状态下，Settings 的静态界面为简体中文。用户自己输入的 Profile 名称、待办、课程和城市名称保持原样。

### MAN-UI-03 中英切换

1. 打开 `Settings → General`。
2. 将语言切换为 `English`。
3. 依次打开八个设置页面，检查侧栏、标题、按钮、选择框、帮助文字和 About 内容。
4. 将语言切回简体中文，再重复检查一遍。
5. 退出程序并重新启动，确认最后选择的语言仍然保留。

预期结果：

- 切换后静态设置文案立即更新，不需要手动编辑配置文件。
- 中英文都没有出现空白标签、原始 key、乱码或控件溢出。
- 切回中文后界面恢复中文，用户数据不被翻译、不被清空。

### MAN-UI-04 天气城市页空间与操作布局

1. 打开 `Settings → Weather`，观察“新增城市检索”区域。
2. 确认搜索输入框和“添加所选城市”按钮位于同一行，分别在左、右两侧。
3. 输入 `苏州` 或 `suzhou`，确认搜索结果列表可以看到候选项；再输入 `朝阳`，确认北京/辽宁等同名候选仍能区分。
4. 观察“已配置的全局城市”列表，滚动查看多个城市。
5. 检查下方“上移、下移、添加城市、移除城市”操作按钮。

预期结果：

- 城市列表有足够高度，城市较多时通过页面/列表滚动查看，不会只显示一两行。
- 四个下方功能键按两列排列，搜索和添加不额外占用一整行。
- 选中城市、设为主城市、排序和删除仍然可操作，确认框不会被设置窗口遮挡。

## 三、主题与字体

### MAN-THEME-01 十二套主题

在 `Settings → Profiles` 中逐个选择以下主题。每次选择后先观察 Dashboard 的即时预览，再点击“保存外观”持久化：

1. Mist Blue
2. Mint Breeze
3. Almond Sand
4. Lavender Cloud
5. Ocean Night
6. Graphite Night
7. Rose Dusk
8. High Contrast
9. Terra Signal
10. Frontier Foundry
11. Astral Transit
12. Coastal Tide

每套主题都检查：

- Dashboard 背景、卡片、边框、主文字和次文字有清楚层级。
- Todo、Agenda、天气和金融小组件的文字没有被背景吞掉。
- 深色主题没有大面积刺眼白底；浅色主题没有低对比度灰字。
- 高对比度主题的标题、正文、按钮、输入框和焦点态都能辨认。
- 切换主题不会改变小组件位置、大小、数据和当前模式。

预期结果：切换下拉框后 Dashboard 立即更新主题，不需要先关闭或重新启动 Settings；点击“保存外观”后重开 Settings 仍保留选择。十二套主题都可以保存和恢复，且没有明显的文字溢出、异常色块、残留旧主题或布局跳动。后四套只作为原创色板和界面语言致敬，不要求出现第三方 Logo 或游戏图片。

### MAN-THEME-02 字体

在同一个 Profile 中依次选择以下字体并保存：

- 系统界面
- 微软雅黑
- Noto Sans
- 思源黑体
- 思源宋体

每次回到 Dashboard，检查 Dashboard 标题、Todo、Agenda、设置入口、数字和中英文混排。

预期结果：

- 字体变化可以在 Dashboard 中看到，或在字体缺失时按预期使用回退字体。
- 中文、英文、数字和符号均可读，没有大片方框、乱码或异常重叠。
- 字体切换不改变网格拓扑，长标题和金融数字仍不会被截断到无法识别。

### MAN-THEME-03 Profile 隔离与恢复

1. 在 `New Profile name` 输入框输入 Profile A 名称，设置一个浅色主题和一种字体，点击“新建配置”。
2. 在同一个页面输入 Profile B 名称，设置一个深色或高对比度主题和另一种字体，点击“新建配置”。
3. 在两个 Profile 之间来回切换，分别回到 Dashboard。
4. 退出程序重新启动，再次切换两个 Profile。

预期结果：每个 Profile 都恢复自己的主题、字体和布局；Todo、课程、城市和金融启用项仍保持为全局数据，不会因切换 Profile 消失或重复创建。

## 四、Dashboard 可读性与交互

### MAN-DASH-01 日常显示

1. 在 Interaction 模式下查看所有当前启用的小组件。
2. 检查窗口宽度较小时的标题、按钮、日期、温度、汇率和指数数字。
3. 如果有金融数据，检查上涨使用红色、下跌使用绿色，并且带有明确的 `+` 或 `-` 符号。
4. 切换到 Locked 模式，尝试点击 Dashboard 上的 Todo 和设置入口。
5. 切回 Interaction 模式，确认 Todo 仍可操作。

预期结果：

- 文字、图标、数字和状态色在十二套主题下都可辨认。
- Locked 模式不会误修改 Todo 或布局；Interaction 模式恢复后操作正常。
- 主题和字体变化不会让已有小组件消失或改变顺序。

### MAN-DASH-02 布局编辑

1. 进入 Layout Edit。
2. 观察编辑提示、保存/取消和组件显示开关。
3. 确认这些控件以浮动工具条显示在 Dashboard surface 外层，不会把网格向下挤压；拖动/缩放时以网格和组件本身判断位置、大小。
4. 在 `DeskBoard` 标题行中间的空白区域拖动看板，确认可以移动窗口；点击标题、网络状态、设置按钮等内容区域不应被误判为拖动。
5. 移动一个小组件并调整大小，选择保存。
6. 再次进入 Layout Edit，确认位置和大小保留。
7. 做一次不同的移动或缩放，选择取消，确认上一次已保存的布局仍在。

预期结果：编辑、保存和取消的行为清楚；浮动工具条不改变网格可用高度，拖动/缩放命中区域不遮挡组件内容；保存布局后切换主题或字体，不应把小组件拓扑重排成不可读状态。

## 五、重启和数据状态

### MAN-PERSIST-01 重启恢复

1. 记录当前语言、Profile、主题、字体、Dashboard 模式和一个布局位置。
2. 正常退出 DeskBoard。
3. 重新启动并打开 Settings 与 Dashboard。

预期结果：语言、当前 Profile、主题、字体和已保存布局恢复；程序不会创建重复 Todo、重复课程或第二个 Dashboard。

### MAN-DATA-01 Data Status 页面

1. 打开 `Settings → Data Status`。
2. 检查页面是否能显示启用项、最近尝试时间、最近成功时间、来源和错误信息区域。
3. 如果当前网络数据可用，执行一次手动刷新并记录结果。
4. 如果网络数据失败，确认已有成功缓存仍然显示，且错误状态不会把上一份成功数据清空。

预期结果：Data Status 能区分“最近一次尝试失败”和“没有成功数据”；网络失败不会破坏已有缓存。此项的网络来源合规性另见 [数据源审计](data-sources.md)。

## 七、通过标准

Task 30 的 UI 人工验收需满足：

- MAN-UI-01 至 MAN-UI-04 全部 PASS；
- MAN-THEME-01 至 MAN-THEME-03 全部 PASS；
- MAN-DASH-01、MAN-DASH-02、MAN-PERSIST-01 全部 PASS；
- MAN-DATA-01 若因外部数据源不可达而无法执行，应标记为 BLOCKED，并单独记录，不得伪造为 PASS；
- 没有崩溃、白屏、乱码、不可读文字、无法恢复的设置或数据丢失。

这份流程只覆盖本轮设置、主题、字体和语言改动；Windows 长时间稳定性、安装包、睡眠唤醒和数据来源公开发布门禁仍需分别按照对应清单验收。
